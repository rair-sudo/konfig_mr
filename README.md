# Эмулятор UNIX-оболочки

Учебный консольный эмулятор UNIX-подобной оболочки. Программа загружает
виртуальную файловую систему из CSV в оперативную память и поддерживает
команды `ls`, `cd`, `head`, `cal`, `rmdir`, `mv`, `vfsinfo` и `exit`.
Изменения VFS не записываются на диск и исчезают при новом запуске.

## Структура

```text
src/                     код эмулятора
tests/                   модульные и интеграционные тесты
vfs/                     примеры CSV-образов
scripts/                 стартовые сценарии и скрипты ОС
docs/interactive-session.txt  запись интерактивного сеанса
run.sh, run.bat           запуск в Linux/macOS и Windows
```

## Установка, запуск и тесты

Требуется Python 3.10 или новее. Сборка и сторонние библиотеки не нужны.
Из корня репозитория:

```sh
./run.sh
./run.sh --vfs vfs/deep.csv
./run.sh --vfs vfs/deep.csv --script scripts/stage5.txt
python3 -m unittest discover -s tests -t . -v
```

В Windows используйте `run.bat` вместо `./run.sh` и `python` вместо
`python3`. Можно также запускать `python -m src.main`. Скрипты `run.sh`
и `run.bat` сначала переходят в корень проекта: относительные пути их
аргументов считаются оттуда.

### Параметры

| Параметр | Назначение |
| --- | --- |
| `--vfs ПУТЬ` | CSV-файл, из которого загружается VFS. |
| `--script ПУТЬ` | Стартовый UTF-8 скрипт команд эмулятора. |
| `--help` | Справка по параметрам. |

Все параметры необязательны. При запуске программа показывает значения
обоих параметров. Если VFS не задана, создаётся пустая файловая система.
При ошибке загрузки показывается сообщение, и работа продолжается с пустой
VFS. Неизвестные параметры запуска отклоняются с ненулевым кодом.

## Команды

Все пути принадлежат VFS, а не реальной файловой системе. Поддерживаются
абсолютные и относительные пути, `.` и `..`. `cd` без аргументов возвращает
в корень VFS. Приглашение отображает фактические имя пользователя и имя
компьютера и текущий каталог VFS. Ввод разбирается с поддержкой одинарных
и двойных кавычек и экранирования. Раскрытие переменных и шаблонов,
конвейеры, перенаправления и запуск программ ОС не реализованы.

| Команда | Назначение |
| --- | --- |
| `ls [-a] [-l] [--] [путь...]` | Список файлов или содержимого папок. |
| `cd [--] [путь]` | Перейти в каталог; без пути — в корень. |
| `head [-n N] [--] файл...` | Показать первые N строк файлов VFS. |
| `cal [год]` или `cal месяц год` | Календарь текущего месяца, года или месяца года. |
| `rmdir [--] каталог...` | Удалить пустые каталоги из VFS. |
| `mv [--] источник... назначение` | Переместить или переименовать элементы VFS. |
| `vfsinfo` | Имя образа и количество папок и файлов в памяти. |
| `exit` | Завершить работу. Аргументы не поддерживаются. |

**Подробности:**

- `ls` сортирует имена, по умолчанию скрывает записи, начинающиеся с `.`;
  `-a` включает их и записи `.` и `..`, `-l` выводит тип и размер файла в
  байтах или число прямых элементов каталога. Флаги можно объединять: `-al`.
  При нескольких путях каталоги выводятся с заголовками.
- `head` без `-n` показывает 10 строк. `-n N` и `-nN` принимают ноль и
  отрицательное N: например, `-n -2` выводит всё, кроме последних двух
  строк. При нескольких файлах добавляются заголовки. Некорректный UTF-8
  заменяется символом замены; чтение из stdin не поддерживается.
- `cal` принимает годы от 1 до 9999 и месяцы от 1 до 12; первым днём
  недели выводится воскресенье. Текущая дата берётся из реальной ОС.
- `rmdir` удаляет только пустые каталоги; корень, текущий каталог и его
  предки защищены. Другие опции, в том числе `-p`, не поддерживаются.
- `mv` переименовывает узел или переносит один либо несколько узлов в
  существующий каталог. Одноимённый файл заменяется; непустой каталог и
  объекты несовместимого типа заменить нельзя. Нельзя переместить каталог
  в самого себя. При переносе текущего каталога или его предка путь в
  приглашении обновляется. Другие опции не поддерживаются.
- Для имён, начинающихся с `-`, используйте разделитель `--`, например
  `head -- -file`. При ошибке в списке источников `mv` или каталогов
  `rmdir` изменения, выполненные для предыдущих операндов, сохраняются в
  памяти; следующие операнды не обрабатываются.

## Стартовые и проверочные скрипты

Стартовый скрипт — текст UTF-8: одна команда на строку. Пустые строки и
строки, начинающиеся с `#`, пропускаются. Для каждой команды выводятся
приглашение, введённая строка и её результат. При ошибке отображаются
сообщение и номер строки, затем выполняется следующая строка. `exit`
завершает скрипт и приложение; иначе после скрипта открывается REPL.
Ошибка чтения скрипта выводится, после чего открывается REPL. Ошибки
команд скрипта сами по себе не меняют код завершения приложения.

| Файл | Назначение |
| --- | --- |
| `scripts/stage2.txt` | Параметры, кавычки, команды и ошибки. |
| `scripts/stage3.txt` | Загрузка VFS, команды и ошибки. |
| `scripts/stage4.txt` | Режимы `ls`, `cd`, `head`, `cal` и ошибки. |
| `scripts/stage5.txt` | `rmdir`, `mv`, работа с VFS и ошибки. |
| `scripts/test_config.sh`, `.bat` | Запуски с разными наборами параметров. |
| `scripts/test_vfs.sh`, `.bat` | Запуски с тремя CSV-образами. |
| `scripts/test_commands.sh`, `.bat` | Запуски сценариев этапов 4 и 5. |

В записи [интерактивного сеанса](docs/interactive-session.txt) показаны
все команды и примеры ошибок в настоящем терминале. Имя пользователя и
компьютера в приглашении на другой машине будут отличаться.

## Формат VFS

Образ — CSV в UTF-8 без BOM с точным заголовком `path,type,content`:

```csv
path,type,content
/docs,dir,
/docs/hello.txt,file,SGVsbG8sIFZGUyEK
/docs/level1/level2/note.txt,file,SGVsbG8K
```

`path` — абсолютный путь от `/`; вложенность задаётся разделителем `/`.
`type` — `dir` или `file`. `content` пуст для каталога, для файла содержит
каноническую запись байтов в base64; пустой файл имеет пустое содержимое.
Если необходимо, CSV-кавычки защищают запятые и кавычки в именах.
Недостающие каталоги создаются в памяти. Строки могут идти в любом порядке;
повторный путь, файл в роли родителя, неверный тип, CSV или base64
считаются ошибкой. До успешной проверки всего образа частичное дерево не
используется. Запись или распаковка исходного CSV не производится.

Примеры: `vfs/minimal.csv` — пустой корень; `vfs/several.csv` — несколько
файлов, включая двоичный; `vfs/deep.csv` — вложенность не менее трёх
уровней и имена с пробелами. Для получения base64 из текста:

```sh
python3 -c "import base64; print(base64.b64encode(b'Hello').decode())"
```

## Пример использования

```text
$ ./run.sh --vfs vfs/deep.csv
user@host:/$ cd "/path with spaces"
user@host:/path with spaces$ head -n 1 "hello world.txt"
Hello, VFS!
user@host:/path with spaces$ mv "hello world.txt" renamed.txt
user@host:/path with spaces$ ls
renamed.txt
user@host:/path with spaces$ cd /missing
cd: No such file or directory: '/missing' (path '/missing')
user@host:/path with spaces$ exit
```
